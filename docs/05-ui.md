# 05 — Interface

## The one rule

> **Color is reserved for data.**

The entire interface is achromatic — ink, paper, hairlines, and precise type. The only
saturated color anywhere in the app is the transferring data itself: the segment map and the
throughput trace. Nothing else is ever colored, including buttons — with exactly one named
exception, the app mark in the corner of the titlebar (§Layout), which is a fixed hue on a
fixed plate that never changes with state and so can never be misread as a reading.

This gives Vortex three things at once:

1. **Instant parse.** Color means motion. Grey means stopped. A user reads the state of
   forty jobs in one glance without reading a single word.
2. **A visual identity that is not a theme.** It survives light mode, dark mode, and
   whatever the OS does next, because it is a rule rather than a palette.
3. **Restraint by construction.** There is nowhere to put a gratuitous gradient.

The reference points are lab instruments and studio hardware — Braun, a spectrum analyzer,
a good audio interface. Quiet chassis, one live readout.

## Signature: the segment map

Every competitor draws a progress bar. Vortex draws **the actual byte-range occupancy of the
file**, live, per worker.

```
collapsed (6 px)
▓▓▓▓▓▓▓▓▒▒▒░░░░▓▓▓▓▓▓▓▓▓▓▒▒░░░░░░░░░░░░░░░░░░░░░
└ complete ┘└ in flight ┘└ not yet ┘

expanded (28 px) — one lane per connection
w1 ▓▓▓▓▓▓▓▓▓▓▓▓▒▒▒▒·································  18.2 MB/s ▁▂▄▅▅▄
w2 ················▓▓▓▓▓▓▓▓▒▒▒▒····················   9.1 MB/s ▂▃▃▂▁▁
w3 ····························▓▓▓▓▓▓▓▓▓▓▓▒▒▒▒·····  21.7 MB/s ▃▅▆▇▇▆
w4 ·······································▓▓▒▒▒▒▒▒   4.4 MB/s ▁▁▂▁▁▁  ← being stolen from
```

It is not decoration. It encodes things the user genuinely wants to know and cannot learn
anywhere else: how many connections are live, whether one is stalling, that a resumed
download really did keep its bytes, and — the satisfying one — the moment the scheduler
takes work away from a slow worker and hands it to a fast one. You watch it happen.

IDM shipped a crude eight-block version of this in 1999 and never improved it. This is the
one thing in Vortex worth being remembered for, so it gets the app's only real animation and
all of its color, and everything around it stays silent.

### Rendering

- `<canvas>`, sized to `devicePixelRatio`, fed by the RLE runs from `ProgressFrame`.
  **Never DOM nodes** — 4,096 blocks as divs is a frame-rate catastrophe.
- 20 Hz for the expanded row, 2 Hz for collapsed rows.
- Only visible rows render, gated by `IntersectionObserver`.
- Runs narrower than one device pixel are **aggregated by coverage** and drawn at partial
  alpha. The map never rounds a partial block up to complete; it must not overstate progress.
- In-flight regions carry a slow directional shimmer — 1.4 s, 8% alpha delta — so "moving"
  is legible without animation noise. Removed entirely under `prefers-reduced-motion`.

### The one orchestrated moment

On job start the map is a single empty bar. As the scheduler brings workers up, split lines
animate in and each lane claims its lease — 220 ms, `cubic-bezier(.2,0,0,1)`, staggered
20 ms. The file visibly *shatters into workers*.

It is the product's core mechanism made visible in a quarter of a second, it happens once
per download, and it is the only place in the app where motion is decorative rather than
functional. Everything else moves in 120–180 ms or not at all.

The canonical copy is `packages/tokens/tokens.css`, loaded by both the desktop window and
the page overlay. `packages/tokens/tests/spectrum.test.ts` asserts every theme declares all
eight lanes, that the two dark blocks are byte-identical, and that no two lanes collide.

**The map is lit, not filled.** One vertical sheen over the painted pixels and a faint glow
around in-flight regions — the only glow in the product, and it is around the bytes actually
moving. Everything else stays matte.

**Typefaces.** *Instrument Sans* for the interface: variable, slightly engineered, a touch
narrow — it holds a dense list without feeling cramped, and it is not the Inter that every
desktop app defaults to. *Commit Mono* for every number: genuinely tabular, calm, and
narrower than JetBrains Mono, which matters when a row carries five numeric fields.

Every numeral in the app is mono and tabular. No exceptions. A proportional digit in a live
speed readout makes the whole row twitch, and that twitch is most of what makes an app feel
cheap.

Frameless window, custom titlebar, 8 px corner radius. Maximised the corner goes to zero, and Windows' own compositor rounding is turned off with it (`chrome::square_corners`) — a maximised borderless window is sized to the work area exactly, so any rounding cuts four notches of desktop out of the screen's own corners. Row height 76 px collapsed.

**One screen.** There was a 200 px column down the left holding the filters and a Settings
link, and it was mostly empty — a handful of short words keeping a fifth of the width away
from the only thing anybody opens this app to look at. The filters are a bar over the list
they filter, Settings is an icon in the titlebar beside the search it sits next to
conceptually, and the window is one thing rather than two panes. No tabs, no toolbar, no
ribbon; the aggregate throughput trace lives in the titlebar because it is the one number
that is true of the whole app.

**The filter bar shows the kinds that exist.** The column always drew Video, Audio, Archives
and Documents so that it had a stable shape. A *row* of chips reading `Video 0 · Audio 0 ·
Archives 0` is four pieces of furniture saying nothing, and across the top there is nowhere
for them to hide — so a chip appears with its first job. The exception is whichever kind is
selected, which stays after its last job is removed, or the chip vanishes under the pointer
that clicked it and the list is left filtered by something no longer on screen. With nothing
downloaded at all there is no bar: an empty state is a sentence inviting somebody to start,
and a row of zeroes over it is the app talking about itself first.

A chip's label sits on the same column as the filenames and the section headings — the chip's
own padding hangs its surface one step to the left, which is what a selected pill is for.

**One list, in three bands.** Active, then Queued, then Done, under sticky headings that
carry the count for the whole band. These were three more entries in that column and they
were never three lists: a job passes through all three while you watch it, so the app was
asking people to follow their own file from section to section — and to go and *check* a
different section to learn whether something had finished. As an ordering it reads as a
sentence, top to bottom: what is happening now, what is waiting to, what already did. A band
with nothing in it has no heading.

That makes the list the one place a row moves on its own, which is worth stating because
everything else in the app refuses to (§Numbers that don't lie or twitch). A job that
finishes leaves the top band and appears in the bottom one. It is the only legible kind of
reorder — the row moved at the moment its state changed, and the heading it moved under says
which state — and the alternative is a list in creation order where something that finished
an hour ago sits above something that is running.

**Forty rows, then more on demand.** The list is not virtualised, and forty is the number the
quality floor is written against. While Done was its own filter that was the whole story;
nobody has two hundred *active* downloads, but one list ends with every download ever
finished. So it renders a page at a time and takes the next when the bottom comes into view —
a screen early, so the rows are there before the scroll arrives. Nothing is fetched: every
job is already in the process, so there is no spinner and no loading state, only more rows.
`Reveal` pages down to reach a row the same way, because a cursor on a row nothing has
rendered is a window that looks like it ignored the click.

**Every row ends on when.** The date and the time, both, right-aligned so the stamps make a
column down the edge of the list — inline at the end of the meta line they would start at a
different x on every row, which is the difference between a field you scan and a field you
read. It says when the job finished if it did and when it started if it did not: one field,
one meaning, which is what lets it stand as a column with no heading over it.

Both halves, always. The first version of this was a ladder — the clock time for today, then
`Yesterday`, then a weekday, then a date — on the theory that each rung should say only as
much as it took to separate a row from its neighbours. It reads well and it answers the wrong
question: a row saying `Yesterday` has told you the day and taken the time away, and a row
saying `14:32` has told you the time and left you to work out the day. A stamp in a list is
for being *the* fact, whole. The year is the one thing that comes and goes, and only when it
is a different year, which is the only time it distinguishes anything. Ordering, separator and
the twelve-or-twenty-four-hour clock are the machine's, not ours.

This is also the thing the app had no way to say at all while Done was a section you switched
to. One list ends with every download ever finished, and *when* is how anybody finds one.

**Settings is a sheet, not a destination**, which is why it is an icon and not a place. Its
button carries `aria-current` while the sheet is open — that says *this is what is open*, not
*you are here*. The glyph is two faders rather than a gear: the gear this set had was a ringed
circle with eight spokes, which is fine beside the word "Settings" and reads as a sun on its
own, one along from a magnifier where a theme toggle would sit.

**Three squares, and Add is the third.** Add was a bordered button reading `+ Add` — the one
control in the bar that said what it did, and the one thing in a 40 px strip heavy enough to
compete with the list under it. As an icon it keeps the last position, so the bar still ends
on the thing you came to press, and it keeps its name in the tooltip and the accessible label.
It is the only plus in the set, and a plus in the corner of a window holding a list has one
meaning.

**The mark is in the corner, and it is the icon.** Same azure plate, same white figure, same
generator (`scripts/logo.mjs`) — not a monochrome reduction of it. That is the one exception
to §The one rule and it is deliberate: colour in this app means bytes, and the mark borrows
nothing from the spectrum's vocabulary, never changes with state, and so cannot be read as a
measurement. What it buys is that the thing in the corner of the window is recognisably the
thing on the taskbar.

It is drawn at 22 px rather than the 20 the rest of the titlebar is built on. The figure alone
does not survive that size — twenty-four hairlines inside twenty pixels is a smudge — but the
figure *on its plate* does, because white on saturated azure is the highest-contrast pair in
the product and the strokes hold a shape there that they lose against paper. Two pixels is the
difference between a legible rosette and a blue square with something in it.

## Screens

### New Download

Opens when the extension hands off a non-video file, or on ⌘/Ctrl-N. One modal surface,
centred in the window, growing in place over 180 ms — not sliding in from an edge, which
put it above the optical centre and left dead space under it.

```
 ╭───────────────────────────────────────────────────────────╮
 │  New download                                             │
 │                                                           │
 │  ubuntu-24.04.2-desktop-amd64.iso                         │
 │  4.9 GB  ·  releases.ubuntu.com  ·  resumable             │
 │                                                           │
 │  Save to    D:\Downloads                        [ … ]     │
 │  Category   Archives                            [ ▾ ]     │
 │                                                           │
 │  ─────────────────────────────────────────────────────    │
 │                                                           │
 │            [ Add to queue ]     [ Download ]              │
 ╰───────────────────────────────────────────────────────────╯
```

`resumable` comes from the real probe (02 §2) — the app knows before the user commits, and
says so plainly. If the server can't resume, it says `single stream` instead, because that
changes what the user should expect.

### Expanded row

Click a row. It grows to reveal the per-worker map, plus:

```
  Connections   12 of 16       adaptive
  Protocol      HTTP/3 · QUIC
  Source        4 addresses · releases.ubuntu.com
  Verified      SHA-256 ✓
  Retries       2 · both recovered
  Started       3 Sep 2025, 14:28
  Finished      3 Sep 2025, 14:33  ·  took 4m 12s
```

**This is where the row's stamp is undone.** Up in the list it has to be one short field in
forty rows; here every value has a label in front of it, so it can be the whole instant — and
the span between the two instants, which is the number this product is actually about. A row
that says `4.9 GB` and `1m 12s` has made the argument for parallel connections without making
a claim. `Finished` is absent until there is one.

`Retries — 2 · both recovered` is deliberate. Showing that the engine hit trouble and
handled it builds more trust than hiding it, and it is the resilience story made visible.

**The live half leaves when the job does.** The map, the per-worker list and `Connections`
all describe work in progress — which connections are open, which one is stalling, the
scheduler moving a lease off a slow worker. A completed or failed job has none of that and
can never get any back, so on one they are gone rather than zeroed: `0 of 16 · adaptive` is
a true number about nothing, and a full-width map is a fatter copy of the bar the collapsed
row is already showing. What is left — protocol, source, retries, and the two instants with
the span between them — is the part that was always about the download rather than about
the moment you happened to be looking. It takes the reading column when it is on its own.
The path and its buttons below are not content and do not: they span the panel and anchor
right, so the buttons land under the × in the row's own corner.

This is the same rule as `Open` and `Show in folder` below, and the same rule as `Finished`:
an element whose only possible outcome is nothing does not get to take up the room.

**`Open` and `Show in folder` appear only when there is a file to point at**, which means a
completed job and nothing else. A failed job's path is where the file *would* have gone and
a running job's bytes are in a `.vxpart` under a different name, so offering either button
there is a control whose only possible outcome is "that file isn't there any more" — an
error message the user asked for by following the interface's own suggestion.

### Remove download

Opens when the × on a *completed* row is clicked, or `Delete` is pressed on one. The same
centred surface as New Download.

```
 ╭───────────────────────────────────────────────────────────╮
 │  Remove download                                          │
 │                                                           │
 │  ubuntu-24.04.2-desktop-amd64.iso                         │
 │  D:\Downloads\ubuntu-24.04.2-desktop-amd64.iso            │
 │                                                           │
 │  ╭───────────────────────────────────────────────────╮    │
 │  │ ☐  Also delete the file from disk                 │    │
 │  │    The file stays where it is, all 4.9 GB of it.  │    │
 │  │    Only the row goes.                             │    │
 │  ╰───────────────────────────────────────────────────╯    │
 │                                                           │
 │  ─────────────────────────────────────────────────────    │
 │                                                           │
 │                     [ Cancel ]     [ Remove ]             │
 ╰───────────────────────────────────────────────────────────╯
```

The list and the disk are two different things, and the × only ever meant the first. That
is the right default and a bad silence — so the app asks once, at the only moment the
answer is cheap: the file is named, its size is on screen, and nothing has happened yet.

**Only for a completed job.** Everything else has no finished file at stake: the engine
writes into `.vxpart` and renames at the very end, and the daemon's `retire` deletes the
partial work whichever way the question is answered. A dialog whose two branches do the
same thing is how an app teaches people to click through its dialogs without reading them.

Ticking the box is a deliberate second act. It arms the destructive branch, the note under
it swaps to say what that costs (`Frees 4.9 GB. There is no recycle bin, so this cannot be
undone.` — the same length as the sentence it replaces, so the button does not move), the
strip takes the 2 px attention edge, and the button renames itself to **Remove and delete**.
No red fill: attention is a left edge here as everywhere else, and a red button would make
every other destructive moment in the app look safe by comparison. `Enter` takes the safe
branch, per §Copy.

### Empty state

```
                     Nothing downloading.

          Drop a link here, or press Ctrl N.
       Vortex catches downloads from your browser
                     automatically.
```

An invitation to act, in the interface's voice. Not an illustration, not a mascot.

### Settings

One scrolling column, sectioned, no tabs. Sections: **Downloads** (folder, categories,
naming), **Speed** (max connections, global limit, schedule), **Browser** (extension status,
capture rules, per-site opt-outs), **Media** (default quality, container, subtitles),
**Advanced** (HTTP/3 toggle, Defender exclusion, logs), **About**.

The max-connections control is a slider with a live note underneath:

> Vortex adjusts automatically per server. This is the ceiling.

Because the adaptive controller is the feature, and a user who sets 32 and sees 2 in use
needs to know that is correct.

## Numbers that don't lie or twitch

The details that separate a premium app from a competent one:

| | |
|---|---|
| **Smoothing** | Speed is EWMA'd with a 3 s half-life *before* display, then rounded to 3 significant figures. A raw per-second readout flickering between 81 and 97 MB/s reads as instability even when the transfer is perfectly steady. |
| **Fixed fields** | Speed, size and ETA sit in fixed-width containers. The row never reflows. |
| **Quantized ETA** | `< 60s` → seconds. `< 60m` → `4m 20s`. Above → `1h 12m`. Never `3,847 seconds`, never a value that changes every frame. |
| **Units** | Displayed in base-10 (MB, GB) to match the file manager and the source page. Computed in MiB internally. Documented, consistent, never mixed — showing 1.2 GB for a 1.29 GB file is the kind of small lie users notice. |
| **Estimates marked** | Manifest-derived video sizes are peak-bitrate estimates and are shown as `~1.2 GB`. Real files land 20–30% under. |
| **No fake precision** | `62%`, not `62.4%`. |

## Motion

| | | |
|---|---|---|
| Micro (hover, focus, press) | 120 ms | `--quick` |
| Standard (modal, row expand, list insert) | 180 ms | `--calm` |
| The shatter | 220 ms, staggered 20 ms | |
| Enter easing | `cubic-bezier(.2, 0, 0, 1)` | `--ease` |
| Exit easing | `cubic-bezier(.4, 0, 1, 1)` | `--exit` |

No springs. No bounce. No parallax. This is an instrument, and an instrument that
overshoots is a broken instrument.

**The asymmetry between the two curves is the whole trick.** A thing arriving decelerates
into place, because the eye has to find it. A thing leaving accelerates away, because the eye
is already on whatever replaced it. Something that fades out on the curve it faded in on
feels reluctant.

**Everything that arrives leaves the same way.** This is the rule that costs something to
keep: CSS cannot animate a node that is about to stop existing, so anything with an exit is a
Svelte transition rather than a keyframe, and the curves have to exist a second time as
functions. They do, in `lib/motion.ts`, next to the argument for why that duplication is
worth it and a test that fails when the two copies drift.

**Nothing moves that the user did not cause.** A row folds open when a download arrives and
folds away when one leaves, because each of those is one thing happening and the fold says
which row and where the space went. Changing the filter is *not* one thing happening — it is
forty rows leaving and forty arriving, and choreographing that is a screenful of movement
that says nothing and lands late. Same for a page appended at the bottom, and for the
daemon's opening list, whose rows were downloading before the window existed. The store
decides, because the row cannot: `queue.animating` is lowered for exactly the flush that
renders a wholesale change, and a transition reads it at the moment it would start.

**A press moves the thing pressed.** Three per cent, which is under a pixel on a 30 px
control. It is the cheapest effect in the interface and most of what separates a window that
feels made from one that feels drawn.

**The mark turns while the queue runs**, twelve seconds a revolution — the one piece of
decoration in the app that is not decoration. Eight arms pulled round is what the mark is
*of*, so a mark that turns exactly while eight workers are pulling is the drawing saying what
it always meant. The plate holds still and the figure turns inside it: a rotating rounded
square would be a spinner, and the plate is the part that has to stay recognisable. It pauses
rather than stops, so it holds the angle it reached instead of snapping back to square every
time the queue goes quiet.

`prefers-reduced-motion` collapses everything to a 100 ms opacity crossfade, removes the
shimmer, and removes the shatter. Two things have to opt out of that rule by name rather than
be shortened by it: the mark's rotation, because a 360° turn compressed to 100 ms is a flick
rather than an absence, and the press scale, because a control that jumps to 97 % and jumps
back is worse than one that does not move. The segment map still updates — it is information,
not animation.

## Copy

The vocabulary is the signposting. An action keeps its name through the entire flow:
**Download** → *Downloading* → *Downloaded*. **Pause** → *Paused*. Never "Submit", never
"Process", never a button whose verb doesn't match the state it produces.

Errors say what happened and how to fix it, in the interface's voice. They don't apologize
and they are never vague:

| ✗ | ✓ |
|---|---|
| `Error: HTTP 403` | **The link expired.** Reopen the page to continue. `[ Reopen page ]` |
| `Download failed` | **The file changed on the server.** `[ Start over ]` `[ Keep both ]` |
| `Insufficient disk space` | **Not enough room on D:.** Needs 2.1 GB more. `[ Change folder ]` |
| `Unsupported format` | **Protected content.** Vortex doesn't download DRM-protected video. |
| `Connection error` | **Lost connection.** Retrying — nothing downloaded so far is lost. |

That last one is the whole product in one line, and it should appear exactly as written.

## Platform polish

| | |
|---|---|
| **Tauri** | `decorations: false`, custom titlebar with `data-tauri-drag-region`, native snap preserved |
| **Windows 11** | Mica backdrop via `window-vibrancy`; taskbar progress via the Tauri progress API — filled to the queue's share while that can be measured, and the indeterminate sweep whenever work is in flight that cannot be (a stream of unknown length, a mux), so a working app never looks like an idle one; jump list for Recent |
| **macOS** | `titleBarStyle: Overlay`, traffic lights inset 20/20; Dock badge |
| **Tray** | Live aggregate throughput in the tooltip; pause-all and open in the menu |
| **Notifications** | One per finished transfer, whether or not the window is focused, never for a cancellation. **Clicking one raises the window and opens that job's row** — moving the filter, and paging the list down, if either is hiding it. A notification that says a download finished and then does nothing when you click it is a worse promise than no notification, so the toast is sent by `src-tauri/src/toast.rs` rather than by `tauri-plugin-notification`, whose desktop path drops the handle the activation arrives on. Nothing is ever notified at the *start* of a transfer: that moment belongs to the browser, where the click happened (03 §2b), and a notification per download is how a download manager teaches people to turn its notifications off. |
| **Reveal** | One name for "somebody outside this window asked for a job": a notification click, and the extension's `Reveal` arriving as `vortex-app --reveal <id>`. Both raise the window and hand the id to the list, which decides what showing it means — clearing a category or a search that is hiding the row, and paging down to it if it falls past what is rendered. The cold case is read as state on mount rather than delivered as an event — the arguments are parsed before the webview exists — and the id is held until the job appears, because on a cold start the list is a round trip behind. |
| **Drag and drop** | A URL, a `.torrent`, or a `.metalink` onto any part of the window |
| **Shortcuts** | `Ctrl N` new · `Space` pause/resume selection · `Ctrl F` filter · `Ctrl ,` settings · `Delete` remove (asks about the file on a finished job) |

## Quality floor

Non-negotiable, and verified before any release:

- **60 fps with 40 jobs listed.** Canvas maps, `IntersectionObserver` gating, Svelte 5 runes,
  no VDOM diff in the hot path.
- **Idle CPU under 0.5%** with the window open and nothing downloading.
- **Full keyboard navigation** with a visible 2 px focus ring at 2 px offset.
- **Contrast ≥ 4.5:1** for all text in both themes.
- **Color is never the sole carrier of meaning** — the worker spectrum is identity, but the
  expanded view also numbers each lane, and state is always written in words.
- **Window restores** to its last size, position and monitor.
- **Cold start under 400 ms** to first painted list.
